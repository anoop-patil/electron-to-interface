## Comments

- Ticket 11: `src/zoom/selection.ts` links each zoom level to the others through Fact IDs. Level 7 shows the step run closest to the Selection until this ticket gives it elements of its own: add its Facts to `FACTS` and replace its entry in `LINKS`.
- Ticket 12: the Reference Library (`app/reference/cpython-3.14.2.json`) records, for each Example, the entries of the handlers that ran on every step run, derived from the gdb captures by `app/reference/example_runs.py`; `src/explain/reference.ts` reads them. Machine code can join each entry, or sit beside it keyed by handler. greet.py's second RESUME is recorded as `RESUME_CHECK` inside `CALL_PY_EXACT_ARGS`.

Built in `app/` and `prototype/tools/`. Decisions made along the way:

- The Reference Library (`app/reference/cpython-3.14.2.json`) gains `machineCode`: each handler the Examples ran, its main part, then its `.warm` and `.cold` parts, every instruction with its address, bytes, mnemonic and operands, and where it jumps or calls. It comes from greet.py's disassembly, which holds all of hello world's handlers; `example_runs.py` checks the two disassemblies agree. Each handler run of an Example gains its `path` (the address of every instruction it ran, in order), the functions it `calls`, and the `values` its inc and dec instructions changed. The Library is about 585 kB, so the page's script grew from 120 kB to 187 kB gzipped. Loading level 7's machine code only when it opens could win that back.
- The user chose to back v7's numbers with a gdb probe: `trace-handler-paths.py` now records the number every inc or dec instruction changes, before and after, and the 3-run check compares those too. The recapture ran exactly the same paths as the committed data, and the probe confirmed every count v7 stated (3 becomes 2, 999 left becomes 1,000, and so on). Notes name them as `{before}` and `{after}`. The build fails if a note on a machine instruction states a number that is neither one of those nor held in the instruction itself (0xd0 is 208; a word is 2 bytes). Three of v7's numbers failed and were reworded: "how many (1)", "48 bytes in" and "yours is step 6".
- v7's hello-world notes on `LOAD_NAME`, `CALL` and `RETURN_VALUE`, with their stage headings, are in the Library's `lineNotes`, keyed by Example, step run and handler. Every other handler run gets v8's generic key lines: the first instruction, calls to named functions (glossed from the Library's `functions`), jumps to the next handler, and checks. Each entry gains a `pathNote`, v8's note on its path, made general with a step's slots.
- RESUME_CHECK's copied code is marked (`copied`) only on the handler run before a step run with no handler of its own. Line numbers alone can't find it: the compiler gives several handlers' last jump a line of RESUME_CHECK's, where their code merged.
- A conditional jump that ran says whether it jumped. One to another handler that didn't jump is a check ("A check: does it need to fall back to CALL? No, so carry on"); a run of identical checks is shown once, with how many there were.
- Level 7's elements are step runs, as levels 5 and 6's are, so it keeps `STEP_RUN` in `LINKS`. greet's second RESUME says its check ran inside CALL_PY_EXACT_ARGS, with a button that selects the step run before it.
- Level 7 is Reference when it shows machine code or says why there is none (a step that never ran, or work done inside another handler), else Typical (`noReference`), with the Observed form Python rewrote the step into. The registers panel is Derived (`registers`). The instruction kinds have design tokens of their own, `--k-move`, `--k-math`, `--k-compare` and `--k-jump`, as in v8.
- The full listings are drawn only when opened: CALL has 1,613 instructions.
- `.github/workflows/data.yml` reruns all three capture tools in an `ubuntu:26.04` container, the release they were run on in WSL, when `prototype/tools`, `prototype/data` or `prototype/examples` change, or by hand. `prototype/tools/compare-data.py` fails it if the output differs from what is committed, apart from the timing, the platform, and the address Python prints for a code object. The new data is uploaded, to commit if it should change. pyelftools and Capstone are pinned, and the platform string now names the Ubuntu release.
- Try it yourself runs the timing command in the browser, labeled Observed, with the step runs the watched run counted. Under it is a sample of the same command run natively, labeled Reference (`tryItSample`). The user chose to capture hello world's own: `trace-handler-paths.sh` now writes `prototype/data/example-hello-cpython-3.14.2.json`. Any other Program shows greet.py's, labeled as greet.py's. A time of 0 gets a note on the browser's coarse clock.
- The commands moved to `src/explain/commands.ts`, so the worker that runs them no longer loads the Reference Library. A command is now filled in as typed, without markup: before, `2**3` in one would have turned bold.
- The Debugger Concept card now says gdb recorded every instruction and the numbers some changed.
